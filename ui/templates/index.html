Reads the five raw logs in the chosen release, rebuilds the daily counts, the labels, the per-user z-scores and the splits, then scores the test split with the frozen checkpoints. The threshold, the standardiser and the weights all come off the checkpoint — nothing is chosen here — and the run asserts that it reproduces the AUPRC already published in outputs/final_results.json.
The menu below names a place to look. What the folder actually is gets decided by its own five header lines.

Off, a model whose release is not this folder's release is refused before anything is derived. On, the run happens and every line of it is labelled a transfer measurement, names the features that are structurally degenerate on each release, and reproduces no published number. The standardiser guard does not relax for it — it inverts, and passes only by proving the checkpoint's transform is foreign to these rows. On a matched run this box does nothing.

Runs the whole pipeline over the chosen folder and keeps the result in models/<run_id>/, where the first button can load it again. Training happens inside a per-run sandbox whose project root is that directory, so the frozen checkpoints in outputs/checkpoints/ are not reachable from it. This takes a long time; run it before the defence, not during.
